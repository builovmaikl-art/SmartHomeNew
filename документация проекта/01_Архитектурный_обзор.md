# 01. Архитектурный обзор

## Назначение

SmartHomeNew — это адаптивная система управления домом с промышленным подходом к безопасности, диагностике и наблюдаемости.

Система построена не как набор независимых автоматизаций, а как единый управляемый pipeline:

```text
IO → INPUT → SCENARIO/SAFETY → COMMAND → DOMAIN OUTPUT → IO
```

Дополнительные слои наблюдаемости:

```text
TRACE / EXPLAINABILITY / DEBUG_VIEW / ADAPT
```

## Основные принципы

- Safety имеет абсолютный приоритет.
- HMI не управляет IO напрямую.
- Scenario не пишет команды напрямую.
- Command Arbitration является единственным владельцем `GVL_COMMAND_SHADOW`.
- Domain PRG пишут только в свои output-GVL.
- `PRG_IO_Write` является единственной финальной точкой физического вывода.
- Debug/Explainability только отображают и объясняют, но не управляют.

## Высокоуровневый поток

```text
Датчики
→ PRG_IO_Read
→ GVL_STATE
→ PRG_Input_Processing
→ GVL_INPUT
→ PRG_Scenario_Engine / PRG_Safety
→ PRG_Command_Arbitration
→ PRG_Heating / PRG_Ventilation / PRG_Water / PRG_Access
→ GVL_*_OUTPUT
→ PRG_IO_Write
→ GVL_IO
```

## Класс системы

```text
Adaptive Safety Control System with Self-Learning Diagnostics
```

Система объединяет:

- fail-safe safety pipeline;
- command-aware IO;
- scenario engine;
- sensor validation;
- anomaly detection;
- confidence/reputation model;
- explainability/debug/HMI view.

## Граница ответственности

| Слой | Ответственность |
|---|---|
| INPUT | нормализация и качество данных |
| SAFETY | hazard detection и safety intent |
| SCENARIO | поведенческие intent и scoring |
| COMMAND | арбитраж safety/user/scenario |
| DOMAIN | расчёт доменных выходов |
| IO_WRITE | финальная запись в физические выходы |
| DEBUG/HMI | read-only наблюдение |
