SMARTHOME NEW — CONSOLIDATED TECHNICAL TASK

1. CORE ARCHITECTURE
1.1. System architecture is centralized and policy-driven.
1.2. Core flow:
Subsystems -> FB_System_Health -> FB_State_Manager -> Policy Layer -> Subsystems
1.3. `GVL_STATE` is transport only and must not be treated as architectural source of truth.

2. SYSTEM MODES
2.1. `NORMAL` — standard operation.
2.2. `DEGRADED` — controlled limitation instead of uncontrolled shutdown.
2.3. `FREEZE_PROTECTION` — damage prevention has priority over comfort.
2.4. `SAFE_STOP` — maximum restriction required by safety logic.
2.5. Priority: `SAFE_STOP > FREEZE_PROTECTION > DEGRADED > NORMAL`.

3. DIAGNOSTICS LAYER
3.1. `FB_System_Health` aggregates subsystem faults.
3.2. Diagnostics classifies fault type: `IO / Sensor / Comm / Subsystem`.
3.3. Diagnostics identifies source: `Heating / DHW / Ventilation / Lighting / Access`.
3.4. First fault is latched as root cause.
3.5. Reset must support both manual acknowledgement and automatic clear when no fault remains.

4. STATE LAYER
4.1. `FB_State_Manager` consumes only abstract health signals and safety state.
4.2. `FB_State_Manager` must not directly arbitrate subsystem-specific diagnostics using transport globals as truth.
4.3. `FB_State_Manager` outputs the aggregated `System Mode` for all policy consumers.

5. POLICY LAYER
5.1. Subsystems must react to `System Mode` only.
5.2. Direct fault-based subsystem arbitration is forbidden.
5.3. Policy overrides scenario, user and local subsystem intent where required by mode.

6. SUBSYSTEM PRINCIPLES
6.1. Heating
- consumes `System Mode`
- publishes degradation upward
- freeze protection has priority over comfort

6.2. DHW
- consumes `System Mode`
- safe stop / freeze protection stop pumps in current architecture
- publishes sensor / IO / degraded signals upward

6.3. Ventilation
- consumes `System Mode`
- degraded mode limits operation conservatively
- safe stop stops ventilation outputs

6.4. Lighting and Blinds
- consume `System Mode`
- scenario and simulation behavior are subordinate to policy
- safe stop forces safe visual behavior according to current design

6.5. Access
- consumes `System Mode`
- opening actions are restricted by policy in dangerous modes
- communication/auth degradation is surfaced upward

7. PROCESS REQUIREMENT
7.1. Architectural changes must be reflected in code and docs consistently.
7.2. Deferred layers such as HMI, logging and optimization must not distort the core architecture.
7.3. Root cause visibility is mandatory for future HMI and event logging.
