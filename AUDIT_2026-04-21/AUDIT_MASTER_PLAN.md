# AUDIT MASTER PLAN

## Цель
Полная верификация логики проекта без изменения кода на этапе аудита.

## Основные правила
- не менять код во время аудита;
- фиксировать только факты текущего поведения;
- не смешивать аудит и рефакторинг;
- проверять проект строго по цепочкам выполнения;
- проверять ownership каждого состояния и команды.

## Ключевые оси проверки
1. порядок выполнения (call order)
2. ownership (кто владеет состоянием)
3. синхронизация состояния
4. безопасность (safety)
5. управление (managers)
6. запись в физические выходы

## Этапы
### Этап 1 — Call order
- MAIN
- последовательность PRG_*

### Этап 2 — Ownership
- System_Mode
- Scenario
- Safety commands
- IO outputs

### Этап 3 — Цепочки
- Safety
- System
- Policy
- Heating
- Ventilation
- Lighting
- Security

### Этап 4 — Cross-cutting
- Latched vs non-latched
- Snapshot / race conditions
- Retry / timeout
- Degraded mode behavior

### Этап 5 — Backlog
- формирование очереди исправлений
- определение зависимостей
- определение приоритетов

## Критерий завершения аудита
- все цепочки пройдены
- все несоответствия зафиксированы
- сформирован полный backlog
- определён порядок рефакторинга
