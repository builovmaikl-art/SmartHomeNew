# AUDIT 2026-04-21

Этот каталог — отдельное рабочее пространство для полного инженерного аудита текущего состояния `SmartHomeNew`.

## Назначение
- зафиксировать порядок полного прохода по проекту;
- отделить аудит от последующего рефакторинга и cleanup;
- собрать все найденные архитектурные, поведенческие и интеграционные несоответствия;
- сформировать строгий backlog исправлений в правильной очередности.

## Состав каталога
- `AUDIT_MASTER_PLAN.md` — главный документ аудита;
- `AUDIT_CALL_ORDER_AND_OWNERSHIP.md` — порядок вызовов, ownership и критические конфликты;
- `REFACTOR_BACKLOG_FROM_AUDIT.md` — очередь исправлений, пополняемая по мере аудита.

## Принцип работы
1. Сначала полностью фиксируется фактическое состояние репозитория.
2. Затем проект проходится по цепочкам вызовов и владельцам состояния.
3. Все найденные несоответствия записываются в audit-документы.
4. Только после завершения полного аудита формируется и выполняется рефакторинг.
5. Cleanup и приведение проекта в порядок выполняются только после устранения архитектурных и поведенческих проблем.

## Базовая последовательность аудита
1. `MAIN.st`
2. порядок вызовов и ownership
3. system mode chain
4. safety action chain
5. heating chain
6. ventilation chain
7. lighting / security / access chain
8. physical output discipline
9. cross-cutting diagnostics, fallbacks, retry logic
10. итоговый backlog рефакторинга

## Правило фиксации
Каждая проблема записывается как отдельная сущность с:
- ID
- категорией
- цепочкой
- файлами / точками входа
- описанием текущего поведения
- риском
- ожидаемым правильным поведением
- рекомендуемым способом исправления
- зависимостями
- приоритетом
